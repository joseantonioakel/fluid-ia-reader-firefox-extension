# Context for coding agents

**Lector Fluido** is a Firefox + Chrome extension that overlays AI-generated summaries on the long
paragraphs of any web page. **Firefox is the primary target.**

## Before touching anything

1. [`docs/ESTADO.md`](docs/ESTADO.md) — what is done, what is verified, what comes next.
2. [`docs/DECISIONES.md`](docs/DECISIONES.md) — why things are the way they are. **Read it before
   changing an architectural decision**: almost every one has a reason that is not obvious from the code.
3. [`docs/prds/lector-fluido-v1.3-prd.md`](docs/prds/lector-fluido-v1.3-prd.md) — the specification.

The project documentation is written in Spanish.

## Commands

```bash
npm run build        # Firefox (default)
npm run build:chrome
npm test             # 165 tests
npm run compile      # wxt prepare + tsc --noEmit
```

Run `npm test` and `npm run compile` before considering any change finished.

## Conventions

- **Language**: comments, documentation and log messages in **Spanish**. Code identifiers in English.
- **UI strings**: never literals in code. They live in `public/_locales/<lang>/messages.json`
  (es, en, fr, de) and are read with `t('key')` from `lib/i18n.ts`. When adding a key, add it to
  **all four** catalogs: a test fails if any is missing. Static pages use `data-i18n` attributes.
- **TypeScript `strict`**, no `any` outside the boundaries of external APIs.
- Comments explain **why**, not what the next line does.
- Every non-obvious business rule has a test. Tests are named after the behavior, not the function.

## Known traps

Mistakes that were already made once and that the compiler does not protect against:

- **The popup is not a tab.** `sender.tab` arrives `undefined` in the messages it sends. If you need
  the `tabId`, send it explicitly.
- **`permissions.request()` requires a user gesture**: call it from the popup, never from the
  background.
- **The content script lives in an isolated world.** Nothing you put on `window` is reachable from the
  page console in Firefox. To expose state, use messaging (`kind: 'debug-extract'`).
- **The Shadow DOM root has `all: initial`**, so `inherit` brings nothing from the page. Pass font
  family, size and line height explicitly.
- **`sans-serif` contains the string `serif`.** When classifying fonts, check for "sans" first.
- **Beware of backticks inside CSS template literals**: they close the string.
- **Credentials never** leave the background nor reach the content script.
- **`const t = theme`** shadows the translation function `t()`. It happened twice while introducing
  i18n: name theme variables `theme`.
- **Returning a Promise from a `runtime.onMessage` listener only works in Firefox.** In Chrome the
  sender gets `undefined`. Always register listeners through `onMessage()` in `lib/messaging.ts`,
  which answers via `sendResponse` in both browsers.
- **Chrome kills the background service worker after 30 s idle.** Long jobs must call
  `keepAliveWhile()` (`lib/messaging.ts`) while they run.
- **`tsc` uses types generated by WXT** for `browser.i18n`. After adding keys to the catalogs, they
  must be regenerated (`npm run compile` already does it) or the typecheck fails with "unknown" keys.

## What is NOT verified

No real call to any provider, no execution in a browser, no overlay seen on screen. The HTTP adapters
are written against each API's documentation, not tested against it. **Do not claim something works
if you have only checked that it compiles.**
